# 车间终端与并行工时

## 已确认的业务范围

浏览器摄像头扫描员工二维码；NFC 通过外接设备输出员工工牌标识，不直接假设浏览器具备 NFC 硬件能力。管理员先登记并授权终端，员工无需管理端账号。本轮不增加终端工作中心范围限制，员工仍只能看本人派工和本人参与的报工。

新提交的单人报工冻结分摊工时，保留原始打卡工时。历史报工保持原口径，不批量重算；整秒尾差按派工顺序给靠前任务。整组任务独占成员，不参与并行等分。

## 入口与授权

| 入口 | 用途 |
| --- | --- |
| `/terminal/manage/` | 系统管理员登记、重新授权、停用终端 |
| `/terminal/manage/cards/` | 管理员搜索、分页打印启用工人／班组长二维码，每页 24 人 |
| `/terminal/activate/` | 使用一次性激活码授权当前浏览器 |
| `/terminal/` | 员工二维码／NFC 标识识别 |
| `/terminal/work/` | 本人任务，运行任务优先，默认待处理，可搜索／切换全部，每页 20 条 |
| `/terminal/tasks/<ID>/` | 开工、暂停恢复、完工、整组成员及小组长移交 |
| `/terminal/reports/` | 本月和上月、本人报工及实际参与的整组报工 |
| `/terminal/reports/<ID>/` | 查看报工；原报工人撤回或改数量重报 |
| `/terminal/auxiliary/` | 开始／提交／撤回本人辅助工时，全部记录分页，每页 20 条 |

终端记录保存随机激活码的 SHA-256 摘要，不存明文。激活码 15 分钟有效，只能使用一次；登记、重新授权、停用均记录管理员操作日志。重新授权和停用递增设备版本，使旧浏览器授权随即失效。

浏览器设备凭据为 Django 签名、HttpOnly Cookie，最长 30 天。员工凭据另有 15 秒签名有效期，绑定设备、设备版本和登录序号；停用员工、停用关联账号、改变角色或终端授权后不能继续访问。工人可以不关联管理账号。每台设备每分钟累计 10 次识别失败后暂时拒绝识别。

进入终端会退出当前管理端登录。终端 Cookie 仅发送至 `/terminal/`，不会授权管理端。所有业务写入均使用 POST、CSRF 校验，员工和业务时间取服务端。终端页面和二维码响应禁止缓存；正式环境 Cookie 使用 Secure，需要 HTTPS。

## 操作与空闲退出

开工、暂停、恢复、组员加入／离开、移交、完工均在线提交，计时使用服务端时间。断网时不保存本地待提交操作，页面提示连接问题；已经开工的任务继续计时。忘记完工仍继续计时，交班组长核对修正。

可信触摸、键盘等操作更新空闲倒计时，并向服务端续期。15 秒无操作会清除页面私有内容并回到识别页；定时状态检查不续期。切到后台后回到页面须重新检查身份，浏览器返回缓存也清除旧内容。多窗口通过登录序号及本地通知识别换人，旧窗口不能清掉新员工的身份。

任务表单含签名状态，绑定操作员工、当前小组长、开工／暂停／在组记录和最新报工状态。重复或过期提交被拒绝。辅助操作也绑定当前登录序号。写入按“月结期间 → 终端 → 员工 → 业务记录”请求锁；整组相关员工按主键顺序锁定。数据库唯一约束限制同派工运行会话、有效报工和同员工运行辅助工时。

普通任务允许并行；整组开工／加入须确认成员没有其他进行中任务或辅助工时，已在整组的员工也不能开始辅助工时。组员必须来自原派工名单，当前小组长必须在组，离开前先移交。

## 工时与历史数据

`WorkSession.ownership_date_snapshot` 在开工时冻结归属日，避免之后修改班次把进行中任务挪到另一归属月；旧会话此字段保持 NULL，继续使用旧的班次推导逻辑。

`PieceReport.original_actual_seconds` 保留开工到完工扣除暂停的原始值。新增可空 `allocated_actual_seconds`，新单人报工提交时计算并冻结。算法读取同员工相连的单人活动时段，以开工、完工、暂停边界切段，仅在当段活动的任务之间等分；按微秒累计为整秒，余数按派工 ID、会话 ID 顺序分配。先提交的快照不因之后完工而重写。

例如任务 A 08:00–09:00，任务 B 08:30–09:30，两者各保留原始 3600 秒，分别冻结为 2700 秒，总计 5400 秒。暂停的任务在暂停期间不参与分配。

有效工时取最新审核修正，其次取冻结分摊秒数（零也有效），最后才取原始秒数。整组和历史报工分摊字段为空，沿用原始／修正值。驳回后重报数量沿用原冻结价格、标准工时和分摊工时；撤回后重新开工是新时段、新提交，会重新冻结。

整组结果显示整组有效数量和员工本人冻结在组秒数，暂不显示尚未实现的个人分配金额。辅助工时沿用原有效分钟口径，不纳入单人计件并行分摊。

## 扫码实现和验证

摄像头在点击后通过 `getUserMedia` 打开，只请求视频，不请求音频。固定版本 jsQR 1.4.0 随静态文件发布，按约 200 毫秒间隔在本机解码，识别成功、停止、切换输入、离开页面时关闭视频流；异步权限结果晚到时同样关闭流。只把二维码标识 POST 给本系统，不上传画面。许可证和来源见 `terminal/static/terminal/vendor/`。

扫码采用可跨浏览器使用的软件解码，没有依赖原生 `BarcodeDetector`。管理员二维码由 qrcode 8.2 生成 SVG，仅管理员可获取。参考：[jsQR 官方仓库](https://github.com/cozmo/jsQR)、[qrcode 官方仓库](https://github.com/lincolnloop/python-qrcode)、[MDN getUserMedia 安全上下文说明](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。

`scripts/test_terminal_ui.cjs` 使用真实二维码像素、模拟摄像头和时间，验证解码、拒绝权限、页面离开后的晚到视频流关闭、15 秒到期、活动续期及页面内容清除，由 Django 测试调用，需要 Node.js 22。没有启动物理摄像头。真实终端摄像头和 NFC 设备需现场联调。

当前 SQLite 无行级锁，生产数据库真实并发尚未验证。计件月结、整组金额分配及导出在管理端办理，见 `SETTLEMENT.md`；易飞连接及字段仍待现场核对。
