# 登录与角色权限

管理端使用 Django 自带账号、密码校验和会话。普通账号必须关联一名启用的员工，账号本身也必须启用。员工与账号沿用已有的一对一关联，不迁移或重建员工数据。

入口：`/accounts/login/`；登录后进入 `/` 工作台。退出只接受带 CSRF 校验的 POST。`/accounts/password/change/` 支持本人修改密码；密码修改后保留当前会话，旧密码和其他浏览器中的旧会话失效。

## 已确认的权限边界

- 班组长仅能管理自己担任班组长的启用班组，可以负责多个班组；同一工作中心的其他班组不自动开放。
- 单人派工和整组派工都要求所有被派人员属于该班组长负责的班组。不允许向无班组人员派工。派工时读取并锁定当前员工记录，不使用调用方缓存的旧班组。
- 派工和报工按派工记录中的班组判断范围；辅助工时按记录中的班组判断范围。员工后来调班不改历史记录的班组归属。
- 审核、修正和驳回仍由班组长执行，且须在本人负责班组范围内。继续允许自派自审。
- 报工反审核仅由启用的系统管理员执行，且归属月份未锁账。状态变更与反审核留痕放在同一事务中；锁定月结期间和报工行，记录操作人、时间及被撤销的审核人、审核时间。
- 月结锁账和解锁由启用的系统管理员执行，解锁继续要求原因。归属月有进行中的生产任务（含暂停、整组）或辅助作业时，须先完工并审核后再锁账。
- 派工人选按已确认口径，继续允许负责班组内所有启用员工，不按角色收紧；终端识别角色范围保持工人／班组长。

## 角色范围

| 角色 | 工作台与现有后台能力 | 业务操作权限 |
| --- | --- | --- |
| 车间工人 | 工作台和业务页面查询本人派工、报工、辅助工时；报工限定本月和上月，不开放 Django 管理后台 | 已授权终端认人、开完工、暂停恢复、本人报工撤回／重报与辅助工时登记；无需管理端账号 |
| 班组长 | 查看负责班组的派工、开工、报工、辅助工时及相关留痕 | 通过派工和审核页面创建任务、审核、修正并通过或驳回 |
| 月结结算 | 只读查看全部报工、辅助工时、月结期间及留痕 | 无审核、反审核、锁账和解锁权限 |
| 工艺人员 | 维护产品、工序和工艺路线，查看工序改单价历史 | 后台自动将当前登录员工记为单价、标准工时的修改人，不能选择他人冒名 |
| 系统管理员 | 维护普通登录账号、员工角色、工作中心、班组、产品、辅助作业类别和易飞映射；只读查看业务记录；登记授权终端、打印员工二维码 | 领域方法允许反审核、锁账和解锁；不替代班组长审核或工艺人员改单价 |

员工角色是普通账号的唯一授权来源。不叠加 Django 用户组、单独权限或 `is_staff` 标记；无需为业务账号勾选“职员状态”。角色变更在下一次权限检查时生效，不缓存旧角色权限。账号或员工停用、员工解绑时，下次请求拒绝访问并清除失效会话。

业务管理员可以新建普通账号、重置普通账号密码，再在员工档案中绑定账号和选择角色。不能维护技术超级用户、设置超级用户标记，或把技术超级用户绑定给其他员工。业务角色不提供删除原始业务记录的权限。

## 首次使用

```bash
uv sync --frozen
uv run python manage.py migrate
uv run python manage.py createsuperuser
uv run python manage.py runserver
```

先用技术超级用户访问 `/accounts/login/`，进入管理后台：

1. 在“用户”中新建普通登录账号，设置密码并启用。
2. 在“员工”中创建或编辑对应员工，填写员工编码、姓名、唯一二维码标识，选择角色并关联登录账号。
3. 班组长账号还须在“班组”中设为相应班组的负责人。
4. 使用普通账号重新登录，工作台按其员工角色显示可访问的记录。

技术超级用户保留 Django 的完整后台维护能力，可以不绑定员工，用于初始化和维护。它不自动充当业务方法需要的员工操作人。正式业务库不创建默认密码或默认业务账号；独立演示库的账号及随机密码见 `MVP_START.md`。

## 范围与验证

已完成账号登录和授权基础、班组长派工审核页面，以及管理员授权的车间终端与 15 秒无操作退出；账号和档案维护继续使用现有后台。业务页面说明见 `DISPATCH_REVIEW.md`，终端的独立身份凭据及数据范围见 `TERMINAL.md`。计件月结查询和正式导出向财务、管理员开放；锁账与解锁仍只允许管理员。参见 `SETTLEMENT.md`。

权限检查位于服务端，后台列表和对象详情共用数据范围。外部调用方应从当前登录账号取得员工操作人，不得接收客户端指定的审核人或派工人；后续业务页面也须使用同一权限与范围检查。

Unfold 侧栏和业务页导航按当前角色显示入口。后台保留各列表的搜索与筛选。全局搜索有跨请求缓存，角色变化后可能显示过期结果，因此停用。

本地沿用 SQLite。事务回滚、锁账后的拒绝操作及重复反审核已有测试；SQLite 不提供数据库行级锁，生产数据库上的真实并发行为尚未验证。正式环境设置 `DJANGO_DEBUG=false` 时启用安全会话和 CSRF Cookie，需通过 HTTPS 访问。
